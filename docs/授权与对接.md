# 仓库授权与其他系统接入

## 无须每次申请的代码共享

2026-10-26 按所有者明确要求，当前仓库已公开，任何人均可查看或下载代码和提交历史，无须邀请。写入和推送仍需协作者权限。下文关于私有协作者的描述是权限选择说明，不代表当前仓库仍为私有。

个人私有仓库的协作者权限粒度有限；如果需要明确区分只读、维护与管理，优先将项目纳入公司组织，使用团队及 Read／Write／Maintain 等仓库角色。实际可选能力以 GitHub 当前设置为准。不得为了方便交接而共享个人 GitHub 密码或令牌。

本次只维护个人仓库，不改变公司仓库权限，也不自动同步到公司目录。公开源码不开放腾讯云、数据库或工作台管理权限。

## 三种权限必须分别开通

1. 源码权限：查看、提交和审查程序。
2. 工作台应用权限：运营、管理者或超管；以共享身份及后端校验为准。
3. 运维／数据库权限：部署程序、访问受限配置或维护数据库。

取得第 1 项不会自动取得第 2、3 项。授权人名单需由负责人明确，不能根据“GitHub 好友”自动开放服务器。

## 其他系统需要怎样接入

当前项目并未实现通用第三方 OAuth／SSO 授权中心，也没有独立服务账号 API。不能直接声称任意系统持员工账号就拥有全部接口权限。

最小交接信息包括：接口前缀、认证方式、身份字段 user_id、角色范围、读写接口、错误码、数据归属、会话失效行为。代码实现以 backend/app.py、identity.py、shared_accounts.py 为准。

如果只需要共享登录，优先复用现有身份服务并给服务独立授权，不分发员工密码；如果只需读取模板，应另设计只读服务账号或受限令牌，并配置有效期、撤销与审计。目前这个专用接入机制属于待开发项，不能将现有员工会话长期硬编码到第三方服务。

只读代码说明可长期分享；真实数据库密码和 SSH 访问通过受控渠道单独交付。仓库一旦获得多人读权限，文件夹和普通 Markdown 不能再单独设置“只有我能看”的访问控制；敏感附件不要提交后再试图靠隐藏链接保护。
