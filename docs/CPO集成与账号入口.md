# CPO 集成与账号入口

更新日期：2026-10-27。

## 使用入口

- 集成入口：https://193.112.27.91:80/creative/prompts
- 左侧导航中部：创意素材 → 提示词工作台。
- 独立入口仍保留：https://193.112.27.91:80/shoe/

登录 AdSight 后，右侧加载工作台，保留 AdSight 左侧导航。工作台内部仍提供模板、反馈、消息、使用说明和管理员维护功能；嵌入模式不再显示第二套账号切换入口，身份由外层 AdSight 管理。

## 账号与数据边界

两端账号使用同一身份库 `amazon_ads.iam`，工作台新增、停用、重置共享账号会作用于同一条身份记录。工作台业务数据继续存放在独立数据库 `shoe_workbench_staging` 的 `shoe_workbench` schema；模板、反馈、附件和统计不会写入 CPO 经营业务表。

此前账号无法进入 CPO 的一个原因是前端没有为 `ai`、`workbench_user` 等角色安排可用首页和导航。现在这些账号可以登录并进入创意素材。普通运营账号若尚未分配有效 CPO 运营组，也可进入工作台，但不会因此获得其他运营组的经营数据。CPO 数据权限仍由原有服务端规则约束。

## 登录连接方式

1. CPO 登录成功后保留自己的登录会话。
2. 集成页面携带当前 CPO Bearer 会话请求 `/shoe-api/auth/from-cpo`。
3. 工作台验证共享身份与账号状态，设置仅用于 `/shoe-embed-api/` 的 HttpOnly、Secure、SameSite=Strict cookie `shoe_embed_session`。
4. 右侧页面 `/shoe/?embedded=adsight` 使用 `/shoe-embed-api/` 访问工作台接口。

独立工作台使用原有 `shoe_session`，嵌入会话使用另一 cookie 和接口路径。两者可在同一浏览器中保持各自身份。凭据不放入网址，也不通过页面消息传递。嵌入登录失效时，只向同源外层页面发送失效事件，由外层返回登录页。
