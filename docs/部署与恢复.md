# 部署、更新与恢复

## 运行路径映射

仓库 `frontend/` 对应服务器 `/home/ubuntu/shoe-workbench-staging/cloud-frontend/`；仓库 `backend/` 对应服务器同根目录的 `backend/`。根目录另有 `.venv312/`、`database.env`、`uploads/`、`backups/`。这些运行目录不随源码一并提交。

`deploy/shoe-workbench.service` 是现网路径样例；`deploy/shoe-routes.conf` 只提供工作台 Nginx 路由片段，不可拿它覆盖整个 CPO 站点配置。备份服务默认调用服务器根目录的 `backup.py`，部署时须将仓库 `deploy/backup.py` 复制到该位置，或同步修改服务路径。

## 初次部署的必要前提

1. 先由获授权 DBA 创建独立工作台数据库及受限应用角色，不能直接将 SHOE_DATABASE_URL 指到 CPO 业务库。
2. 在工作台库按编号执行 `migrations/001_initial.sql` 至 `015_version_labels_and_revisions.sql`，之后依次执行 `backend/credential_vault.sql`、`backend/collaboration.sql`、`backend/notification_context.sql`、`backend/reply_lifecycle.sql`，每项记录结果。这些后续脚本是已上线结构的一部分，不能遗漏。当前没有自动迁移执行器；不可每次启动重跑整套 SQL。`backend/credential_identity_access.sql` 属于共享身份库的授权，须另行审查，不能当工作台迁移执行。
3. 由 DBA 检查 CPO `iam` 表和角色结构，再评估 `deploy/configure_shared_identity.py`；它会授予账号表写权限并增加角色，是有影响的管理步骤，不是安全的自动健康检查。
4. 私下配置 `.env.example` 对应变量，真实文件权限限制为运维服务所需；不提交到 GitHub。
5. Python 3.12 创建独立环境，安装 backend/requirements.txt；部署前端与后台，创建 uploads 和 backups。
6. 安装工作台服务，检查 health；在现有站点审查后增加工作台路由，检查 Nginx 配置，再平滑重载。
7. 登录验证、发布模板、提交反馈、图片、通知及共享账号行为逐项检查。不要向真实员工广播测试公告。

历史 seed.json 可用于空白环境初始化素材，但不是完整生产数据库。deploy/initialize_templates.py 读取环境变量 SHOE_DATABASE_URL，只向空的模板／卖点表导入；已有库会跳过。deploy/provision_workbench_db.py 是历史数据库角色授权脚本，仅限 DBA 在结构迁移完成后审查使用；拒绝覆盖既有 database.env。此归档不提供不经审查的一键生产部署。

在线集成测试放在 tests/，运行前将仓库 backend 加入 PYTHONPATH，并配置受控环境变量；例如 Linux 中使用 `PYTHONPATH=backend python tests/live_usage_and_notice.py`。测试可能改动共享账号和业务数据，只在获得授权并了解清理范围后执行。

## 程序更新

先核对服务器源码版本→代码检查和测试→备份工作台库及 uploads→将新文件传到临时位置→语法与依赖检查→替换程序→重启 shoe-workbench→检查 /health 与真实网页。整个过程不重建数据库，不删除 uploads，不重置共享账号。

涉及字段结构变化时须新增编号迁移，不可偷偷改历史迁移冒充新版本。CPO 无关文件不应在本项目部署中替换。

## 内容更新

2026-10-26 后续结构：上述 001—015 和 backend 中后续 SQL 完成后，依次执行 `migrations/016_feedback_template_reference.sql` 与 `migrations/017_help_center.sql`。新后台需包含 `help_center.py`；不能仅更新 app.py 而遗漏模块。使用说明现通过多篇文章维护，旧 settings.help 已保留迁移为入门文章，新内容请使用新界面或新文章接口管理。

管理员在网页保存草稿、前台试填、发布新版本；发布内容进入工作台数据库。GitHub 修改 README 或提交源码不会自动发布数据库模板。

## 备份与恢复

当前 shoe-backup.timer 每日触发，带随机延迟。deploy/backup.py 保存工作台数据库 dump 与 uploads 压缩包到本机 backups。它不备份共享 IAM 库，也没有自动删除旧备份的保留策略。请另由公司配置身份库备份和离机副本。

程序问题优先回退代码，不回退数据库；数据恢复先暂停写入，在隔离库恢复并核验关联，再决定切换，避免覆盖备份之后的新反馈。不能只恢复数据库却丢失对应图片。共享 IAM 的恢复可能同时影响 CPO，必须另行协调。
