# 版本名称与微调发布

更新日期：2026-10-24。已部署至腾讯云工作台，未推送 GitHub。

## 管理员使用

- 首次发布使用“发布新版本”。
- 小调整使用“更新当前版本”：保持当前显示名称、内部版本编号，不新增运营可见历史版本，使用统计仍合并在同一版本。
- 需要单独对比的改动使用“发布新版本”：创建新的版本条目，由管理员决定，不按字数自动判断。
- 在历史面板点击版本名称旁的铅笔，可以修改显示名称，如将原 v2 改名为 v1。若已有未删除的同名版本，先处理同名条目；不允许同一模板保留两个同名版本。
- 删除旧版本或归档模板后，其记录默认退出看板、趋势和高频词统计，不会继续显示核验模板。
- 历史面板的“清理统计”只针对该版本；数据面板选择模板后“清理此模板统计”针对该模板全部现有统计，不限当前筛选周期。需要二次确认。此操作不删除收藏、模板或反馈；新事件可以重新累计。

## 内部数据边界

版本的数字主键不重排，显示名称保存在 template_versions.display_name。改名不会把内部 v2 的事件关联到被删除的内部 v1。创建新版本时，显示名称依据仍存续的 vN 名称继续编号；内部编号仍单调增加。

小调整前的内容快照保存在 version_revisions，并增加 template_versions.revision；它是后台修订记录，不是每次都展示为新的运营版本。目前没有独立的内部修订恢复界面，不要声称有对应的用户自助恢复功能。小调整不是跨版本对比，旧内容与新内容使用次数会合并，重要改动应选择新版本。

events、field_usage 的 stats_excluded 用于从统计中排除旧记录，避免不可恢复删除原始事件。对已清理字段的下一次记录，会从 1 开始累计，不会重新带回清理前次数。删除版本和归档模板的原始数据仍留在库内供运维排查，默认前台不展示。

需执行迁移 015_version_labels_and_revisions.sql。保留现有 001—014，不重新导入 seed。涉及 shared IAM 的表未作修改。

## 验证

在线集成测试通过：管理员改名、重复名称拦截、普通用户拒绝、小调整保留编号、内部快照保存、已删版本与归档模板排除、清理后重新累计。

浏览器实测通过：独立模板首次发布后微调仍只有一个版本；铅笔改名后历史面板更新；版本清理按钮成功执行；默认看板不再出现旧核验模板和已删版本。新建核验模板已归档，未改名、清理或删除真实业务模板。
